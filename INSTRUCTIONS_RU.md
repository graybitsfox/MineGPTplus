# Инструкция по запуску и подключению к РЕАЛЬНОМУ СЕРВЕРУ

Здравствуйте!

Предыдущая версия кода была настроена на работу с тестовым сервером. Эта инструкция поможет вам настроить бота для подключения к **любому реальному серверу Minecraft**, как лицензионному (online-mode), так и "пиратскому" (offline-mode).

## 1. Установка зависимостей (если нужно)
```bash
npm install
```

## 2. Настройка файла `.env`

В корне проекта вам нужно создать (или отредактировать) файл `.env`. **Именно здесь вы указываете, куда и как бот будет подключаться.**

Скопируйте в него приведенный ниже шаблон и **внимательно** заполните его в соответствии с настройками вашего сервера.

```dotenv
# === ОБЯЗАТЕЛЬНЫЕ ПАРАМЕТРЫ ===

# IP-адрес или доменное имя вашего сервера
MINEGPT_HOST=your_server_ip_here

# Порт вашего сервера (стандартный - 25565)
MINEGPT_PORT=25565

# Версия Minecraft, на которой работает сервер (например, 1.18.2, 1.20.1)
# ВАЖНО: должна точно совпадать с версией сервера!
MINEGPT_VERSION=1.18.2


# === АУТЕНТИФИКАЦИЯ ===
# Выберите ОДИН из двух вариантов ниже.

# --- ВАРИАНТ А: Для лицензионных серверов (online-mode=true) ---
# Укажите email от вашей учетной записи Microsoft и пароль.
# Бот будет заходить под вашим лицензионным аккаунтом.
# MINEGPT_USERNAME=your_microsoft_email@example.com
# MINEGPT_PASSWORD=your_microsoft_password

# --- ВАРИАНТ Б: Для "пиратских" серверов (offline-mode=false) ---
# Укажите любой свободный никнейм. ПАРОЛЬ ОСТАВЬТЕ ПУСТЫМ.
# Бот зайдет без аутентификации.
MINEGPT_USERNAME=BotAlice
MINEGPT_PASSWORD=

```

**Как пользоваться шаблоном:**
- **Раскомментируйте** строки, которые вам нужны (уберите `#` в начале).
- **Закомментируйте** тот вариант аутентификации, который вы **не** используете.
- **Заполните** своими данными.

## 3. Запуск

После настройки `.env` файла, запустите проект командой:
```bash
npm start
```
В этой обновленной версии для теста будет запускаться только **один бот**. В консоли вы увидите подробные логи его подключения. Если вы увидите сообщение "Successfully connected and spawned", значит, все настроено правильно!

Если подключение не удалось, проверьте еще раз все параметры в `.env` файле, особенно **версию** и правильность выбранного **способа аутентификации**.
